# 授权故障排查

如果系统设置已经打开 BigBigMouse 的辅助功能开关，菜单栏仍显示「等待辅助功能授权」，请按 [完整排查步骤](../Resources/授权故障排查.txt) 操作。同一份说明也包含在 DMG 中。

优先重新打开应用、确认运行位置、移除旧授权再添加新版；只有前面步骤无效时，才手动使用系统的 `tccutil` 重置本应用的授权。应用不会自行修改系统授权记录。

## 已观察到的情况

0.1.1 排查时，菜单栏运行的是项目构建目录里的副本，而安装版已放在 `/Applications`。两份副本具有相同 Bundle ID 和代码签名；路径差异是已确认的混淆因素，不能单凭它断定授权失败的完整原因。

退出应用、使用系统工具重置本应用的辅助功能授权、清除应用偏好并从 `/Applications` 重新安装和授权后，用户确认恢复正常。这是一次组合操作的成功记录，并不证明其中某个单独步骤必然能修复所有同类问题。

## 0.1.2 的改进与边界

- 普通启动仅接受系统或当前用户的「应用程序」文件夹；其他位置提示先安装，不创建滚动监听，也不弹系统授权请求。
- 若新进程发现另一位置的副本正在运行，明确显示双方路径并退出新进程，避免两个监听器同时反转滚动。
- macOS 有时会把打开应用的操作直接交给既有进程，新版本的代码不会执行。因此，更新前仍需从菜单栏退出旧版本。
- 等待授权或启动失败时，可定位当前副本，或通过恢复入口重新打开。重新打开会等待旧进程退出，再初始化滚动监听。
- 返回应用或打开菜单时会重新检查权限。只有系统认可权限并且滚动监听成功启动，才显示已开启。
- 本地 ad-hoc 签名没有稳定的 Developer ID 身份。授权恢复提示不能替代公开分发前的正式签名与公证，也不保证所有系统版本上的权限缓存行为相同。

技术参考：[Apple 辅助功能授权检查](https://developer.apple.com/documentation/applicationservices/1459186-axisprocesstrustedwithoptions)、[Developer ID 分发](https://developer.apple.com/developer-id/)。
